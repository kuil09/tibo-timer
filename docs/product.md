# 제품 계약

## 목적

방문자가 Tibo의 최신 공개 발언을 근거로 Codex 리셋 예정 시각을 자신의 시간대에서 확인한다. 제공하는 답은 개인 계정 상태가 아니라 공지의 해석이다.

## 화면

첫 화면은 최근 리셋 공지의 결과와 예정 시각을 우선한다. 확정 가능한 시각이 있으면 방문자 시간대의 시각과 남은 시간을 보여주고, 확정할 수 없으면 사용자 관점의 짧은 상태만 보여준다. 근거가 되는 원문으로 이동할 수 있어야 한다.

최근 발언 영역은 작성 시각과 원문을 중심으로 보여준다. 내부 처리 상태, 모델별 판단, 수집 주기, 공급자 상태, 운영 메타데이터는 이 화면의 정보 계층에 포함하지 않는다.

각 최근 발언 카드에는 세 모델의 유효한 합의로 채택된 최종 판정 요약을 원문과 함께 표시한다. 표시 내용은 리셋 종류, 판정 상태, 해석된 방문자 시간대의 시각이며, 개별 모델 판단·모델명·근거 문자열·내부 처리 상태는 표시하지 않는다. 판정이 없거나 세 모델이 일치하지 않은 발언도 대기·미확정 상태로 숨기지 않는다.

일반 사용량 리셋과 추가 리셋권 지급은 결과에서 구분한다. 정확한 예정 시각만 초 단위 남은 시간을 표시한다. 대략적인 시각은 `경`, 기한은 `이전`으로 구별한다. 예정 시각이 지나면 경과 상태이며 실제 완료라고 단정하지 않는다. 더 새로운 미확인 발언이나 취소 공지가 있으면 이전 일정을 현재 답으로 표시하지 않는다.

실제 계정 상태를 직접 조회하는 서비스가 아니므로 필요한 최소한의 오해 방지 문구는 허용한다. 구현 방식이나 내부 판단 절차를 설명하는 문구는 그 역할을 대신할 수 없다.

## 사용자 노출 문구 계약

구현 요구사항은 사용자 노출 콘텐츠가 아니다. 기능을 구현하는 데 쓰인 기술, 컴포넌트 이름, 내부 상태나 디버그 개념을 화면 설명으로 자동 승격하지 않는다.

다음 다섯 유형을 기본적인 copy leakage로 취급한다.

1. **Spec-to-Copy Leakage**: 기획서, 범위, 요구사항 문장이 사용자 문구로 노출됨
2. **Implementation Narration**: 기술, 라이브러리, 모델, 처리 구조를 화면에서 설명함
3. **Developer-Note Leakage**: 운영자나 개발자를 위한 메모와 장애 원인이 사용자에게 노출됨
4. **Criteria-to-Copy Leakage**: acceptance criteria, 검증 조건, 평가 기준을 사용자에게 설명함
5. **Debug/Metadata Leakage**: 수집 시각, polling 주기, 모델 ID, 내부 처리 상태 같은 메타데이터가 노출됨

적용 원칙:

- 사용자의 다음 판단이나 행동에 직접 필요한 정보가 아니면 기본적으로 화면에 추가하지 않는다.
- 요구사항에 명시되지 않은 visible text를 새로 만들거나 기존 문구를 바꾸지 않는다.
- label, caption, badge, helper/status text를 구현을 설명하기 위한 장식으로 임의 추가하지 않는다.
- `WebGL`, `Three.js`, renderer, 모델/provider명, 내부 상태명 같은 구현 세부는 제품상 필요한 정보로 별도 승인된 경우에만 노출한다.
- 장식용 컴포넌트는 별도 문구 요구가 없으면 textless가 기본이다.
- 구현 변경은 사용자 copy 변경 없음이 기본이며, copy 변경은 별도의 제품 변경으로 취급한다.
- 내부 관찰 가능성은 사용자 화면이 아니라 저장소 상태, 로그, Actions 등 운영 채널에서 확보한다.

기능 이슈에서 새 문구를 허용하지 않을 때는 다음 계약을 명시할 수 있다.

```md
## Approved user-visible copy

NONE
```

`NONE`은 해당 작업에서 새로운 사용자 노출 문구를 추가할 수 없다는 뜻이다. 문구가 필요한 작업은 이 절에 승인된 문구를 명시한다.

### Snapshot은 승인이 아니다

`tests/ui-copy.snapshot.json`은 **현재 감사된 copy 집합의 변경 감지 장치**다. snapshot에 문자열을 추가하는 행위만으로 제품 copy가 승인되는 것은 아니다. 새 문구는 먼저 사용자 가치와 위 leakage 유형을 기준으로 검토되어야 하며, 그 검토를 통과한 뒤 snapshot을 갱신한다.

런타임에서 생성되는 의도적 제품 문구는 `public/copy.mjs`를 관리 지점으로 사용한다. `public/view.mjs`는 표시 상태를 계산하되 headline 문구를 소유하지 않는다. `public/app.mjs`는 사용자 노출 문자열을 직접 하드코딩하지 않고 copy contract를 통해 사용한다. 접근성 속성, 내부 ID와 코드 심볼은 실제 화면 copy와 구분한다.

## 처리 계약

수집은 FxEmbed 최신 페이지 한 번, 최근 24시간만 대상으로 한다. 원문·원문 URL·작성 시각을 유지하고 작성자 ID와 핸들을 검증한다. 원문이 잘렸거나 한 번의 입력 한도를 넘으면 원문만 제공한다. 원문 변경은 이전 해석을 폐기한다. 수집 성공 시 현재 최신 페이지에 없는 자료는 현행 데이터에서 제외한다. 과거 기록을 추가 수집하지 않는다.

추론은 OpenRouter의 서로 다른 제작사·모델 세 개가 같은 원문 묶음을 독립적으로 해석한다. 변경된 원문 최대 8개, 총 16,000자, 한 실행에 세 요청이다. API의 모델 카탈로그에서 가격이 전부 0인지 확인한 뒤, 실제 요청에도 입력·출력·요청당 상한 0을 지정한다. 자동 모델 라우터나 유료 대체 경로는 없다.

응답 필드는 발언 ID, 사건 유형, 상태, 조건 여부, 정확한 근거 인용, 정확한 시간 표현이다. 각 인용이 원문에 존재하는지 검증한다. 시각 계산은 발언 작성 시각 기준 상대 시간, 명시적 ISO 시각, 날짜·시각·시간대가 해석 가능한 표현을 지원한다. `PT`와 `ET`는 해당 지역의 서머타임을 적용하고, 시계가 중복되거나 존재하지 않는 경계 시각은 미정으로 둔다. 표현을 해석할 수 없거나 시간대가 없으면 임의의 시각으로 바꾸지 않는다.

세 개의 유효한 결과에서 사건·상태·조건·계산 시각이 모두 일치한 경우만 결과를 채택한다. 일부 모델 성공을 세 모델 합의로 간주하지 않는다. 조건부 공지에는 정밀 타이머를 붙이지 않는다. API 키는 서버에만 있고 방문자의 시간대는 브라우저 안에서만 사용한다.

공개 `status.json`은 브라우저가 제품 결과를 안전하게 표시하는 데 필요한 최소 projection만 포함한다. 모델 목록, 개별 vote, 내부 분석 상태, 수집 점검 시각 같은 운영 메타데이터는 공개 projection에서 제외한다.

## 운영 계약

UTC 날짜 기준 최대 45개 추론 요청. 예약 장부를 API 호출 전에 커밋·푸시한다. 중단되거나 실패한 요청도 예약량을 환급하지 않는다. 전체 실행은 동시성 그룹으로 직렬화하고 저장소 충돌 시 강제 푸시하지 않는다. 외부에서 같은 계정으로 발생한 OpenRouter 호출은 이 장부가 셀 수 없다.

실패한 발언은 한 시간 후 재시도하며 최대 세 차례 시도한다. 실패 모델은 여섯 시간 제외해 같은 모델을 곧바로 다시 고르지 않는다. 운영자가 실패한 모델을 제외 목록에 추가한 경우에는 다음 실행에서 다른 무료 모델로 재시도한다. 잘못된 응답과 실패는 완료로 표시하지 않는다.

키 누락, 공급자 오류, 수집 실패 같은 운영 원인은 내부 상태로 보관한다. 사용자 화면에는 그 원인을 그대로 노출하지 않고 `최신 공지를 확인할 수 없습니다`처럼 제품 관점에서 필요한 결과만 표시한다. 오래된 원문은 현재 예정 시각으로 노출하지 않는다. GitHub 예약 실행은 지연될 수 있어 정확히 20분마다 수집된다는 보장은 없다.

`Product checks`는 네트워크 없이 제품 회귀 테스트를 실행한다. UI copy 검증은 snapshot 일치뿐 아니라 대표적인 구현/운영/메타데이터 leakage 문자열과 내부 분석 surface가 다시 DOM에 연결되는지도 검사한다. `Update and publish Tibo Timer`는 수집·추론·정적 빌드·Pages 배포를 수행하고 배포된 산출물을 빌드 결과와 비교한다.
