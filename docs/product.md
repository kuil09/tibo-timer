# 제품 계약

## 목적

방문자가 Tibo의 최신 공개 발언을 근거로 Codex 리셋 예정 시각을 자신의 시간대에서 확인한다. 제공하는 답은 개인 계정 상태가 아니라 공지의 해석이다.

## 화면

첫 화면은 최근 공지의 상태와 예정 시각을 우선한다. 숫자로 확정할 수 없는 때는 이유를 표시하고 원문을 제공한다. 모델별 근거는 접힌 상세 영역에 둔다. 방문자에게 모델 선택이나 추론 실행을 요구하지 않는다.

일반 사용량 리셋과 추가 리셋권 지급을 구분한다. 정확한 예정 시각만 초 단위 남은 시간을 표시한다. 대략적인 시각은 `경`, 기한은 `이전`으로 구별한다. 예정 시각이 지나면 경과 상태이며 실제 완료라고 단정하지 않는다. 더 새로운 미확인 발언이나 취소 공지가 있으면 이전 일정을 현재 답으로 표시하지 않는다.

## 처리 계약

수집은 FxEmbed 최신 페이지 한 번, 최근 24시간만 대상으로 한다. 원문·원문 URL·작성 시각을 유지하고 작성자 ID와 핸들을 검증한다. 원문이 잘렸거나 한 번의 입력 한도를 넘으면 원문만 제공한다. 원문 변경은 이전 해석을 폐기한다. 수집 성공 시 현재 최신 페이지에 없는 자료는 현행 데이터에서 제외한다. 과거 기록을 추가 수집하지 않는다.

추론은 OpenRouter의 서로 다른 제작사·모델 세 개가 같은 원문 묶음을 독립적으로 해석한다. 변경된 원문 최대 8개, 총 16,000자, 한 실행에 세 요청이다. API의 모델 카탈로그에서 가격이 전부 0인지 확인한 뒤, 실제 요청에도 입력·출력·요청당 상한 0을 지정한다. 자동 모델 라우터나 유료 대체 경로는 없다.

응답 필드는 발언 ID, 사건 유형, 상태, 조건 여부, 정확한 근거 인용, 정확한 시간 표현이다. 각 인용이 원문에 존재하는지 검증한다. 시각 계산은 발언 작성 시각 기준 상대 시간, 명시적 ISO 시각, 날짜·시각·시간대가 해석 가능한 표현을 지원한다. `PT`와 `ET`는 해당 지역의 서머타임을 적용하고, 시계가 중복되거나 존재하지 않는 경계 시각은 미정으로 둔다. 표현을 해석할 수 없거나 시간대가 없으면 임의의 시각으로 바꾸지 않는다.

세 개의 유효한 결과에서 사건·상태·조건·계산 시각이 모두 일치한 경우만 결과를 채택한다. 일부 모델 성공을 세 모델 합의로 간주하지 않는다. 조건부 공지에는 정밀 타이머를 붙이지 않는다. API 키는 서버에만 있고 방문자의 시간대는 브라우저 안에서만 사용한다.

## 운영 계약

UTC 날짜 기준 최대 45개 추론 요청. 예약 장부를 API 호출 전에 커밋·푸시한다. 중단되거나 실패한 요청도 예약량을 환급하지 않는다. 전체 실행은 동시성 그룹으로 직렬화하고 저장소 충돌 시 강제 푸시하지 않는다. 외부에서 같은 계정으로 발생한 OpenRouter 호출은 이 장부가 셀 수 없다.

실패한 발언은 한 시간 후 재시도하며 최대 세 차례 시도한다. 실패 모델은 여섯 시간 제외해 같은 모델을 곧바로 다시 고르지 않는다. 운영자가 실패 모델을 제외 목록에 추가한 경우에는 다음 실행에서 다른 무료 모델로 재시도한다. 잘못된 응답과 실패는 완료로 표시하지 않는다. 키 누락·공급자 오류·수집 실패는 운영 상태로 노출한다. 오래된 원문은 마지막 성공 시각과 함께 남기되 현재 예정 시각으로 노출하지 않는다. GitHub 예약 실행은 지연될 수 있어 정확히 20분마다 수집된다는 보장은 없다.

`Product checks`는 네트워크 없이 제품 회귀 테스트를 실행한다. `Update and publish Tibo Timer`는 수집·추론·정적 빌드·Pages 배포를 수행하고 배포된 HTML, JavaScript, CSS, JSON을 빌드 결과와 비교한다. 외부 처리 실패라도 안전한 상태 화면을 배포한 뒤 작업을 실패로 보고한다.
